# czx_bridge 功能规格（Feature Spec）

> 2026-09-16。独立 MOD，RimWorld RimTalk 类比：**游戏状态/事件流出去，AI 生成的内容与指令流回来**。
> 本文件定义"需要有哪些功能"；传输层细节见 `design_bridge_architecture.md`。

---

## 0. 产品形态

```text
[WH3 游戏进程]                          [外部]
┌─────────────────────────────┐      ┌──────────────────────────┐
│ czx_bridge agent (Lua)       │      │ czx_bridge daemon (Python)│
│  采集器 ──► 序列化 ──► 写出   │ ──►  │  解析 ──► 事件总线 ──► API │
│  摄入器 ◄── 校验  ◄── 读入   │ ◄──  │  后端适配器(LLM/脚本/工具)  │
│  注入器 ──► UI 文本显示       │      │  配置/预算/健康检查        │
└─────────────────────────────┘      └──────────────────────────┘
         ▲ 消费方 mod 注册（czx 等）          ▲ 外部客户端
```

- **campaign 和 battle 两个上下文都要覆盖**。RimTalk 的"对话"体验在 WH3 主要发生在战役层（领主/外交/叙事），战斗层是战术数据；campaign 侧 `cm:model()` 数据面远比 battle 丰富，采集更容易。
- agent 与 daemon 通过**文件/日志**通信（WH3 Lua 无 socket），daemon 对客户端暴露本地 API。

## 0.5 应用场景

按"谁在用、得到什么体验"组织。每个场景标注依赖的功能域（F 编号）与成熟度分级。

### S1 AI 指挥官 / 军师模式（核心场景，czx 的入口）

玩家把军队托管给 AI，同时外部 LLM 以"军师"角色旁观战局：读战场快照 → 用自然语言给出意图级指令（"左翼收缩""集火敌方领主"）→ agent 校验后下发给 czx 执行；同时把决策理由以文本注入游戏（"左翼压力大，已命矛兵补位"）。

- 依赖：F1 + F3 + F2 + F4；czx 提供执行层
- 体验：RTS 里"将军接受参谋建议"的模式——AI 提意图，本地战术引擎执行
- 成熟度：P0（bridge 存在的首要理由）

### S2 战地实况解说（Battle Caster）

事件流驱动实时解说：接战、溃逃、领主单挑、占领点易手 → daemon 调 LLM/模板 → 文本注入 UI（或外部 TTS 朗读）。适用：观战局（托管代打）、直播、AI vs AI 观赛。

- 依赖：F1.2 + F2.1/F2.2；可选外部 TTS（daemon 侧朗读，游戏不参与音频）
- 体验：自带解说员的战斗回放感
- 成熟度：P1（F2 链路验证后即可）

### S3 角色扮演台词（RP Banter / 单位会"说话"）

RimTalk 的直接对应物：按 faction/lord 人设生成台词——卡尔·弗兰茨接战放狠话、鼠人溃逃时吱吱叫、混沌领主胜利宣言。事件触发 + 冷却 + 人设模板可扩展（社区可贡献 persona 包）。

- 依赖：F1.2 + F2.3/F2.5；campaign 侧领主交互扩展
- 体验：战斗有了角色感和代入感
- 成熟度：P1

### S4 战役编年史 / 叙事日志（Campaign Chronicler）

回合事件驱动自动撰写战役日志："第 47 回合，帝国攻下玛丽恩堡，远征军回防阿尔道夫……"可导出为图文战报/小说化文本，或注入 UI 做回合简报。

- 依赖：F1.3 + F1.4 + F2.4；存储用 F5.2
- 体验：每个战役自动生成一部战史，可分享
- 成熟度：P2（campaign 覆盖后）

### S5 新手教练 / 战术顾问（Coach Mode）

外部 AI 旁观**玩家自己操作**的战斗，实时给战术建议："你的骑兵孤军深入""敌方左翼正在包抄"。是教学工具也是新手辅助。

- 依赖：F1 + F2.2（只读+建议，不发指令 → 零控制风险）
- 体验：等于免费实时战术教练
- 成熟度：P1；**不含 F3 指令通道，最安全的外部 AI 用法**

### S6 直播互动 / 弹幕指挥（Chat Commands）

直播观众弹幕投票决定 doctrine/意图："rush！"→ daemon 聚合 → intent 指令下发。Twitch/B 站弹幕接入 daemon 的客户端 API 即可。

- 依赖：F3 + F5.3；延迟秒级天然适配
- 体验：观众参与指挥的直播玩法
- 成熟度：P2

### S7 数据仪表 / 赛后复盘（War Room & Replay）

daemon 实时仪表盘：双方兵力曲线、热点图、击杀统计；赛后自动生成战报（含图表 + 叙事摘要）。回放工具：拖入录像文件重放时间线。

- 依赖：F1 + F5.2 + F7
- 体验：全战终于有了像样的战后统计（原版战斗结算极简）
- 成熟度：P1-P2

### S8 沙盒导演 / 剧本战役（Story Director）

内容创作者预写事件脚本："第 60 秒兽人增援从南侧入场 → 触发旁白文本"。daemon 按剧本/条件注入文本与 intent 指令，辅助制作战斗视频/剧情场景。

- 依赖：F3 + F2 + F5.4 自定义脚本后端
- 体验：半自动化 Machinima 导演台
- 成熟度：P2

### S9 MOD 开发辅助 / 调试观察（Dev Tool）

开发者实时查看游戏内部状态流：单位当前意图、控制权归属、事件触发序列——调试其它 battle mod 的现成观察窗（czx 自己的校准回路就吃这个）。

- 依赖：F1 + F5.1
- 体验：不用翻日志文件，结构化状态实时流
- 成熟度：P0（开发期最先受益）

### S10 无障碍辅助（Accessibility）

战斗事件转外部 TTS 语音播报："你的 3 号单位正在溃逃"——为视力受限玩家提供听觉反馈通道。

- 依赖：F1.2 + daemon 侧 TTS
- 成熟度：P2，但价值独立于其它场景

## 0.6 战役层：宏观决策与回合进度

### 关键洞察：LLM 更适合战役层

| 维度 | battle 层 | campaign 层 |
|---|---|---|
| 决策节奏 | 实时，秒级延迟致命 | 回合制，LLM 几秒延迟无感 |
| 决策粒度 | 单位级微操（外部做不了） | 宏观动作（移动/外交/建造/科研） |
| 数据面 | battle_unit API 有限 | `cm:model()` 全量世界状态，远比 battle 富 |
| 执行风险 | 抢控制权实时冲突 | 无实时控制权争夺，失败可恢复 |

**分工结论：战役层是外部 AI/LLM 的主场；战斗层是 czx 规则引擎的主场。** 桥把两边接起来——campaign 宏观意图甚至可以翻译成 battle 开打时的初始 doctrine。

### 三个自治等级（按风险递增）

```text
L-OBSERVE   只读顾问：读全量战役状态 → 战略建议文本注入
            （"经济养不起两支满编""格里姆格下回合大概率宣战"）
            零执行风险，第一个交付

L-ADVISE    提案-批准制：AI 产出宏观提案 → 用原生 dilemma/事件 UI
            弹给玩家确认 → 玩家点"接受"才执行
            安全边界：AI 永远不直接动玩家的游戏

L-AUTOPILOT 全自动回合：外部 brain 直接驱动宏观动作序列
            → 自动结束回合 → 下一回合。即"AI 打战役"观赛模式
            独立工程量级，最后做（可选，非主线）
```

### 宏观动作可行性矩阵（执行面逐项过）

| 动作 | 落地通道 | 可行性 |
|---|---|---|
| 读全量状态（派系/军队/城市/外交/财政/科技/任务） | `cm:model()` 系列 | ✅ 最容易，campaign 数据面最大 |
| 战略建议注入 | dilemma/event feed/advisor 文本 | ✅ F2 同链路 |
| 移动军队 | `cm:move_to` 类脚本函数 `[需验证]`；兜底 UI 模拟点击 | ⚠️ 中 |
| 宣战/外交动作 | `cm:` 外交函数族（CA 剧情脚本在用）`[需验证]` | ⚠️ 中 |
| 建造/拆除 | `cm:add_building_to_settlement` 类 `[需验证]` | ⚠️ 中 |
| 招募/解散 | `cm:grant_unit_to_character` / UI 招募面板模拟 `[需验证]` | ⚠️ 中 |
| 科研选择 | 科技 UI 模拟点击 | ⚠️ 中 |
| 英雄事务官行动 | UI 模拟 | ⚠️ 中 |
| **结束回合** | UI 组件 `SimulateClick` 结束回合按钮 | ✅ 可行（mod 圈已有 UI 点击先例） |
| 技能点/装备界面 | UI 重度操作 | ⚠️ 易碎，建议留人工 |
| 战斗结算 | 自动战斗 UI / `cm:` 函数 `[需验证]` | ⚠️ 中 |
| 存档/读档 | `cm:save`/`trigger` 自动存档钩子 `[需验证]` | ✅ 可做 |

⚠️ 原则：**凡是 UI 模拟路径都脆**（分辨率/界面布局/时序依赖）——能走 `cm:` 函数就走函数，UI 模拟只作兜底，且每次调用前后校验结果状态。

### 回合进度控制（独立小功能，单独可用）

- 自动结束回合（可选条件：无待处理事件才结束）
- 事件触发暂停（"有重要决策时停下等玩家"）
- 回合节奏统计（每回合耗时、AI 思考耗时进遥测）
- 自动存档钩子（每 N 回合 + 关键节点前）

### 战役层场景补充

- **S11 AI 打战役观赛**：L-AUTOPILOT——外部 LLM 全自动扮演某派系，玩家观赛；直播/研究价值高，工程量大，P3
- **S12 战略顾问常驻**：L-OBSERVE——每回合简报+威胁预警+经济诊断，P1
- **S13 批准式执政官**：L-ADVISE——AI 提案玩家批准，体验上最像"AI 副官"，P2（比 AUTOPILOT 更推荐先做）

### 战役层与 czx 的衔接点

```text
campaign 宏观意图（LLM：本回合目标=守住北境）
   → bridge 传递 → battle 开打时 czx 初始 doctrine=防御向
战役里"我军劣势要避战"→ 战斗触发时提示撤退倾向
```

宏观意图 → 战斗 doctrine 的映射表是 czx 侧的设计点，bridge 只负责把意图送进战场初始化。

## 1. 功能清单

### F1 状态采集与导出（核心）

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F1.1 battle 快照 | 每 tick：双方阵容、单位位置/HP/士气/状态/控制方/当前目标 | P0 |
| F1.2 battle 事件流 | 离散事件：开战/接战/溃逃/单位阵亡/技能释放/占领点易手/胜负判定 | P0 |
| F1.3 campaign 快照 | 回合事件钩子：派系、军队位置、外交、财政、领主状态（`cm:model()` 全量可读） | P1 |
| F1.4 campaign 事件流 | 回合开始/宣战/合邦/围城/英雄行动/任务完成 | P1 |
| F1.5 结构化协议 | `SNAP/EVT/DEC` 行协议或 JSONL，版本化 | P0 |
| F1.6 采样控制 | 快照频率、字段掩码、事件过滤可配置 | P1 |

### F2 AI 内容注入（RimTalk 核心体验 = "游戏里有东西在说话"）

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F2.1 文本注入通道 | daemon 产文本 → agent 读入 → 游戏 UI 显示。battle 侧有 Infotext Manager/advice；campaign 侧有 event feed/advisor `[需验证具体 UI 通路]` | P0 |
| F2.2 战地解说员 | 事件驱动的实时战况解说（"左翼骑兵接战了"），冷却+去重防刷屏 | P1 |
| F2.3 角色化对话 | 按 faction/lord 人设模板生成台词（领主接战放狠话、溃逃哀嚎、胜利宣言）——RimTalk 的直接对应物 | P1 |
| F2.4 战役叙事 | 回合简报、外交事件点评、远征日志 | P2 |
| F2.5 提示词模板 | 消费方可注册 persona/模板，daemon 侧组装 prompt | P1 |
| F2.6 本地兜底文案 | LLM 不可用时降级到规则模板文案，注入链路不断 | P1 |

### F3 指令摄入（外部 → 游戏）

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F3.1 指令白名单 | 只允许意图级：set_doctrine / set_intent / retreat / config / say | P0 |
| F3.2 schema 校验 | agent 侧校验失败 = 丢弃 + 日志，fail-closed | P0 |
| F3.3 消费方路由 | 指令按 mod 字段路由到注册 handler | P0 |
| F3.4 输入合成兜底 | io 读不可用时，daemon 合成热键触发预设指令 | P1 |

### F4 消费方接口（mod 对 mod）

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F4.1 `register_source(id, fn)` | 消费方挂自己的快照采集器，bridge 统一序列化输出 | P0 |
| F4.2 `register_handler(id, fn)` | 指令路由到消费方 | P0 |
| F4.3 `push_event(id, evt)` | 消费方主动推事件（如 czx 的 DECISION）入事件流 | P0 |
| F4.4 `inject_text(id, text, channel)` | 消费方请求文本注入显示 | P1 |

### F5 外部 Daemon

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F5.1 采集器 | tail 日志 / 轮询遥测文件 → 行解析 → 内部事件总线 | P0 |
| F5.2 状态存储 | SQLite 落库 + 最近 N tick 环形缓冲 | P1 |
| F5.3 本地客户端 API | localhost HTTP/SSE/WebSocket：状态订阅 + 指令提交端点 | P1 |
| F5.4 后端适配器 | OpenAI 兼容 endpoint / 本地模型 / 自定义脚本，插件式注册 | P1 |
| F5.5 配置管理 | endpoint/model/key/预算/开关，配置文件或 UI | P0 |
| F5.6 健康检查 | agent 心跳超时 → 标记离线 → 通知客户端降级 | P0 |
| F5.7 预算与限流 | token 预算、每分钟上限、事件合并去重 | P1 |

### F6 可靠性与降级

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F6.1 fail-safe | daemon 不在/崩溃 → agent 静默停用，游戏零影响 | P0 |
| F6.2 心跳握手 | 版本协商 + 存活性双向确认 | P0 |
| F6.3 指令过期 | 指令带时间戳，超过 N 秒未消费自动丢弃（战场已变） | P1 |
| F6.4 重连恢复 | 中场断线 → 重连后补 SYNC 帧恢复上下文 | P1 |
| F6.5 性能护栏 | 单 tick 采集/序列化超时则跳帧降级，绝不拖帧 | P0 |

### F7 录制与回放

| 子功能 | 说明 | 优先级 |
|---|---|---|
| F7.1 遥测落盘 | SNAP 帧流即录像带 | P1 |
| F7.2 离线 replay | 帧序列喂给 lua.exe 重放决策模块 | P1 |
| F7.3 回放分析工具 | daemon 侧：战斗报告、时间线、指标统计 | P2 |

## 2. 明确不做（Non-goals）

| 不做 | 原因 |
|---|---|
| 单位级外部微操指令 | 延迟/冲突不可控，接近外挂，偏离定位 |
| 内存注入/改游戏文件 | 脆弱且越界 |
| 联机/PVP 支持 | 社区同类 mod 的已知雷区（desync/公平性），单机限定 |
| daemon 随游戏自启 | 首版手动启动；自动拉起做进后续版本 |
| 云存档/远程服务 | localhost only，不碰网络暴露面 |
